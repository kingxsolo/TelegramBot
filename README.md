# تلجرام_بوت

**المستودع:** [github.com/kingxsolo/TelegramBot](https://github.com/kingxsolo/TelegramBot) · **الإصدار:** [v1.0.0](https://github.com/kingxsolo/TelegramBot/releases/tag/v1.0.0)

مكتبة عربية للتعامل مع Telegram Bot API بلغة Solan. توفر عميل HTTP مع JSON، رفع وتنزيل الملفات، long polling، موجّهًا للرسائل والأوامر والأزرار والاستعلامات، ومساعدات لإنشاء لوحات المفاتيح. كما أن `بوت.طلب(اسم_الطريقة, المعطيات)` يتيح استدعاء **أي طريقة** في Bot API، حتى الطرق التي تُضاف بعد إصدار المكتبة.

تتبع المكتبة أسلوب وحدات Solan: ملف `solan.json` في جذر الحزمة، ومدخل `رئيسي.سو`، ولا يلزم بناء أو اعتماديات خارجية.

## التثبيت

من مستودع GitHub (يتطلب صلاحية الوصول إلى المستودع):

```sh
solan add تلجرام_بوت=kingxsolo/TelegramBot@^1.0.0
```

ثم في البرنامج:

```solan
استورد "تلجرام_بوت"
خل بوتي = تلجرام_بوت.بوت(بيئة("TELEGRAM_BOT_TOKEN"))
اطبع(بوتي.معلومات())
```

أو من مجلد نسخة محلية استورد ملف المدخل مباشرة:

```solan
استورد "/مسار/solan-telegram/رئيسي"
```

المكتبة تحتاج صلاحية الشبكة. لا تضع رمز البوت في مصدر عام؛ خزّنه بمتغير بيئة أو سرّ خارجي. لا تفعّل `تحقق_tls: غلط` في الإنتاج.

## إرسال الرسائل واستدعاء الطرق

```solan
استورد "تلجرام_بوت"
خل بوتي = تلجرام_بوت.بوت(بيئة("TELEGRAM_BOT_TOKEN"))
خل انا = بوتي.معلومات()
خل نتيجة = بوتي.رسالة(123456789, "أهلًا من Solan", {"parse_mode": "HTML"})

// واجهة عامة لكل الطرق، بالاسم الرسمي الذي توثقه Telegram:
خل اعضاء = بوتي.طلب("getChatAdministrators", {"chat_id": -1001234567890})
```

العميل يرسل JSON عبر HTTPS، يفك رد Telegram، ويعيد قيمة `result`. عند `ok=false` أو فشل الاتصال يرمي خطأ `خطأ_تلجرام` مع الحقول `رسالة` و`رمز` و`وصف` و`تفاصيل` و`تجاوز_المعدل` و`اعادة_بعد`. إعدادات العميل الاختيارية: `عنوان_api` لتشغيل خادم Bot API مخصص، `مهلة` بالثواني، `تحقق_tls`، و`رؤوس` إضافية. `محاولات_429` (افتراضيًا صفر) يحدد عدد مرات إعادة المحاولة عند رد 429 الصريح، مع احترام `retry_after`. لا يعيد العميل محاولات أخطاء الشبكة تلقائيًا لأن Telegram قد يكون نفذ POST قبل انقطاع الرد، وإعادته قد تكرر الإجراء. يقبل أيضًا `ناقل` كدالة `(url, خيارات_http) -> {حالة, جسم}` لتخصيص النقل أو حقن fake API.

الدوال المختصرة تشمل معلومات البوت، الرسائل والردود والتعديل والحذف، الصور والملفات والصوت والفيديو والموقع وفعل الكتابة، إجابة أزرار callback والاستعلامات inline، إدارة webhook، وروابط الملفات. كل معطيات API الإضافية تمرر كقاموس خيارات.

## رفع وتنزيل الملفات

```solan
بوتي.رفع_صورة(معرف_المحادثة, "./صورة.jpg", {"caption": "صورة"})
بوتي.رفع_ملف(معرف_المحادثة, "./تقرير.pdf", {"caption": "التقرير"})
خل رابط = بوتي.رابط_ملف(معرف_الملف)
بوتي.تنزيل_ملف(معرف_الملف, "./download.bin")
```

كما يمكن رفع مجموعة حقول عبر `طلب_ملفات(الطريقة, المعطيات, الملفات)`. قيمة كل ملف إما مسار نصي، أو قاموس بالشكل الذي تتطلبه شبكة Solan: `{"ملف": المسار, "اسم_الملف": الاسم}`. تدعم واجهة HTTP في Solan multipart، لكن حدود حجم الرفع تعتمد على Bot API المستخدم وإعداداته.

## الاستطلاع ومعالجة التحديثات

`استطلاع(معالج, خيارات)` يستخدم `getUpdates` ويحدّث `offset` تلقائيًا. خياراته المعروفة: `offset` و`timeout` و`allowed_updates` و`تأخير_الخطأ` و`عند_خطأ`. يوقفه استدعاء `بوتي.ايقاف()` من معالج أو مسار تنفيذ آخر. لا يمكن تشغيل getUpdates مع webhook نشط في الوقت نفسه وفق قواعد Telegram.

```solan
خل موجّه = تلجرام_بوت.موجّه()
موجّه.عند_امر("start", دالة(رسالة, تحديث, ب) {
  ب.رد(رسالة, "أهلًا " + رسالة.from.first_name)
})
موجّه.عند_زر(دالة(زر, تحديث, ب) {
  ب.اجابة_زر(زر.id, "تم")
})
موجّه.عند_نص(دالة(رسالة, تحديث, ب) {
  ب.رد(رسالة, "وصلني: " + رسالة.text)
})
موجّه.تشغيل(بوتي)
```

الموجّه يدعم الرسائل والتعديل والمنشورات والقبول قبل الدفع والشحن والتفاعلات والعضوية والاستطلاعات وبيانات Web App والاستعلامات inline والأزرار، وأي update جديد عبر `عند_نوع` أو `عند(نوع, شرط, معالج)`. المعالج يأخذ `(الجزء المطابق، التحديث الكامل، البوت)`. `استخدم` يضيف middleware بترتيب التسجيل؛ توقيعه `(التحديث، البوت، التالي)`، واستدعاء `التالي()` يكمل السلسلة، واستدعاؤه مرتين يرمي خطأ. `عند_خطأ(معالج)` يسجل error boundary يأخذ `(الخطأ، التحديث، البوت)`. معالجات `عند` العادية مستقلة؛ أما `عند_في_مجموعة(اسم, نوع, شرط, معالج)` فيشغّل أول معالج مطابق فقط في المجموعة، وتُعالج المجموعات بترتيب أول تسجيل لها. يمكن للموجّه استدعاء `ايقاف_التوجيه()` لوقف المجموعات اللاحقة. المرشحات `مرشح_و` و`مرشح_او` و`مرشح_ليس` تركب دوال الشروط.

```solan
موجّه.استخدم(دالة(تحديث, ب, التالي) {
  اطبع("وصل update: " + نص(تحديث.update_id))
  التالي()
})
دالة معالج_النص(رسالة, تحديث, ب) { ب.رد(رسالة, رسالة.text) }
موجّه.عند_في_مجموعة("عام", "message", دالة(ر) { ارجع ر.احصل("text", عدم) != عدم }, معالج_النص)
```

وتتوفر `عند_نمط(تعبير, معالج, خيارات)` لفحص النصوص بمحرك `نمط` المدمج.

## لوحات المفاتيح وتحليل الأوامر

```solan
خل لوحة = تلجرام_بوت.لوحة_ضمنية([
  [تلجرام_بوت.زر_ضمني("موقعنا", {"url": "https://example.com"})],
  [تلجرام_بوت.زر_ضمني("موافق", {"callback_data": "ok"})]
])
بوتي.رسالة(معرف_المحادثة, "اختر", {"reply_markup": لوحة})
خل اجزاء_الامر = تلجرام_بوت.امر("/help arg1 arg2")
```

تتوفر `لوحة_رد` و`ازالة_لوحة` و`اجبار_رد` كذلك. ومنشئات الأزرار الجاهزة تشمل callback، الرابط، Web App، التحويل إلى inline، النسخ، الدفع، طلب جهة الاتصال، وطلب الموقع. ويمكن تكوين الأنواع الرسمية الأخرى مباشرةً بواسطة `زر_ضمني(النص, الخيارات)`؛ يمرر القاموس خصائص الزر الرسمية مثل `login_url` و`switch_inline_query_chosen_chat` و`callback_game`. Telegram يتحقق من القيود الخاصة بكل نوع، مثل وضع زر الدفع أو اللعبة في أول صف.

لإنشاء لوحات ديناميكية استخدم `باني_لوحة_ضمنية()` أو `باني_لوحة_رد(خيارات)` ثم `اضف(زر)` و`صف()` و`وزع([أحجام_الصفوف])` و`صدّر()`. توجد أيضًا `نتيجة_مقال` و`نتيجة_صورة` و`محتوى_نصي` لنتائج الاستعلامات inline؛ مرّر الأنواع الأخرى كقاموس API مباشر إلى `اجابة_استعلام`.

## الجلسات والمحادثات

`جلسات()` ينشئ مخزنًا في الذاكرة للعملية الحالية. تمرير مسار JSON يحفظ الحالة محليًا ويحمّلها عند إنشاء المخزن لاحقًا. مفتاح الجلسة افتراضيًا يجمع معرف المستخدم والمحادثة، ويمكن تحديد نطاق `user` أو `chat`. تشمل الواجهة `بيانات` و`اضبط_بيانات` و`حالة` و`اضبط_حالة` و`امسح`، وتقدم `افتح_حوار` واجهة `حالة` و`انتقل` و`بيانات` و`اضبط` و`الغاء`.

```solan
خل مخزن = تلجرام_بوت.جلسات("./حالة-البوت.json")
خل حوار = تلجرام_بوت.افتح_حوار(مخزن, تحديث)
حوار.انتقل("انتظار_الاسم")
حوار.اضبط("الاسم", "سارة")
```

`مخزن.وسيط()` يرفق الجلسة بالتحديث ويحفظ بعد انتهاء middleware التالي. التخزين JSON محلي، غير مشفر وغير موزع؛ لا تضع الأسرار فيه، واستخدم مخزنًا خارجيًا عند تشغيل عدة عمليات أو الحاجة إلى ضمانات التزامن.

## النطاق والتوافق

Telegram Bot API واسعة وتتغير باستمرار. بدل إعادة تنفيذ كل طريقة يدويًا، توفر المكتبة واجهة عامة `طلب` تغطي جميع الطرق الحالية والمستقبلية، مع دوال مختصرة للسيناريوهات المتكررة. جميع الحقول والمعطيات الموثقة تمرر بصيغتها الرسمية (مثل `chat_id`, `parse_mode`, `reply_markup`) داخل القاموس. استخدم أسماء الطرق الرسمية بالإنجليزية. طرق Bot API التي تتطلب multipart تُستخدم عبر `طلب_ملفات`.

يدعم الاستقبال long polling وخادم webhook فعليًا. سجّل عنوانك العام لدى Telegram بواسطة `بوتي.ويبهوك("https://example.com/telegram/webhook", {"secret_token": "سر_عشوائي"})` ثم ابدأ خادم الاستقبال:

```solan
بوتي.خادم_ويبهوك(8080, موجّه, {"مسار": "/telegram/webhook", "سر": "سر_عشوائي", "عنوان": "0.0.0.0"})
```

الخادم يقبل POST فقط على المسار المحدد، ويتحقق من `X-Telegram-Bot-Api-Secret-Token` عند تمرير سر، ويفك JSON ثم يمرر التحديث إلى الموجّه. ويمكن تمرير `شهادة` و`مفتاح` عند إنهاء TLS داخل Solan؛ وإلا ضع reverse proxy HTTPS أمامه، إذ يتطلب Telegram عنوان webhook عامًا صالحًا بـ HTTPS. لا تشغّل `استطلاع` وwebhook في الوقت نفسه.

## الاختبارات

من جذر الحزمة:

```sh
solan tests/اختبار.سو
solan --check رئيسي.سو
```

الاختبارات محلية ولا تحتاج رمز بوت أو اتصالًا بحساب Telegram. تشمل routing وmiddleware وfilters، جلسات JSON، keyboard builders، نتائج inline، وfake transport لإعادة محاولة 429. استخدم `ناقل` لكتابة استجابات وهمية إضافية لاختبار منطق تطبيقك دون Telegram.

## مصادر التصميم وحدود النقل

قورنت أنماط التوجيه والجلسات وإعادة المحاولة وwebhooks والرفع والاختبار في وثائق [python-telegram-bot](https://docs.python-telegram-bot.org/)، و[aiogram](https://docs.aiogram.dev/)، و[pyTelegramBotAPI](https://pytba.readthedocs.io/)، و[Telegraf](https://telegraf.js.org/)، و[grammY](https://grammy.dev/)، و[node-telegram-bot-api](https://github.com/yagop/node-telegram-bot-api). هذه المشاريع تعمل في runtimes مختلفة؛ نقلت أفكارًا مناسبة مثل middleware والمجموعات والجلسات وretry الاختياري وkeyboard builder وtransport قابل للحقن، لا تفاصيل asyncio أو streaming أو adapters الخاصة ببيئات JavaScript.

المكتبة متزامنة وتعتمد على HTTP وملفات Solan. لا تدّعي توفير asyncio/Promises، أو streaming uploads، أو adapters لـExpress/Fastify/Cloudflare، أو مخازن Redis/SQL جاهزة. `طلب` يستدعي أي طريقة Telegram تقبل JSON، أما الطرق التي تتطلب multipart فتستخدم `طلب_ملفات`. لا يوجد wrapper مستقل لكل endpoint؛ يظل Bot API المرجع النهائي لصحة الحقول وصلاحيات البوت.
